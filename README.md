# WB · РНП Дашборд

Управленческий дашборд для Wildberries в формате сайта (один HTML-файл).
Семь вкладок: **Главная** (сводный P&L), **Динамика заказов**, **Оборачиваемость**
(с расчётом дозаказа), **Товар** (карточка товара и сравнение периодов),
**Финансы** (отчёт о реализации по дням), **Аналитика** (ABC-анализ по прибыли,
список убыточных товаров и товаров, где реклама не окупается, % возвратов) и
**Инструкция** (интерактивная справка: поток данных и частые вопросы).

Все таблицы по товарам используют единое правило «товар был активен в периоде»
(были продажи, возвраты или реклама), поэтому число товаров совпадает между
Главной и Аналитикой. Служебные удержания без продаж (напр. мелкое возмещение)
в списки не попадают, но полностью учтены в итоговых суммах.

Все расчёты идут **прямо в браузере**, данные никуда не отправляются — то, что вы
загружаете, остаётся только в вашем браузере (IndexedDB/localStorage).

## Код доступа

Зашитый снимок данных (финансы, реклама, каталог) хранится **зашифрованным**
(`wb-secure.js`, AES-256-GCM; ключ выводится из кода доступа через PBKDF2-SHA256).
В исходниках сайта — только шифртекст, поэтому цифры не видны тому, у кого нет кода.
При открытии дашборд просит код, расшифровывает данные **в браузере** и показывает их.
Код можно «запомнить на этом устройстве» (хранится в localStorage) и сбросить кнопкой
**«Выйти»**. Сменить код — пересобрать `wb-secure.js` с новым кодом.

> Замечание про историю git: файлы удалены из текущей версии, но если репозиторий
> публичный, старые коммиты с прежними плейнтекст-данными остаются в истории.
> Полное удаление из истории — отдельная операция (перезапись истории).

## Как открыть

- **Локально:** дважды кликнуть по `index.html` — откроется в браузере.
- **Как сайт:** залить на любой статический хостинг. Проще всего — **GitHub Pages**:
  Settings → Pages → Source: ветка репозитория → папка `/root`. Через минуту
  дашборд будет доступен по ссылке вида `https://<логин>.github.io/dashboard/`.

Файл самодостаточный: стили и скрипт внутри `index.html`. Внешняя сеть нужна только
для разбора `.xlsx`-отчётов (парсер SheetJS подгружается с CDN по требованию).

## Откуда берутся данные

1. **Каталог товаров и история заказов** — собирается из вашей личной таблицы учёта и
   файла себестоимости, вместе с финансами/рекламой шифруется в `wb-secure.js`.
   Пересобирается целиком, когда вы присылаете новую выгрузку — это делается через
   Claude, не на сайте.
2. **Воронка продаж по дням** (вкладка «Товар») и **отчёт о реализации** (вкладка
   «Финансы») — загружаются **прямо на сайте**: перетащите `.xlsx`-файл(ы) из личного
   кабинета WB в область загрузки. Разбор идёт в фоновом потоке (Web Worker), поэтому
   страница не подвисает даже на больших файлах. Каждая загрузка добавляется к уже
   накопленным данным (совпадающие даты просто обновляются, не дублируются); хранится
   скользящее окно 90 дней.
   Дашборд сам отделяет ваши товары от остального кабинета — по совпадению «Артикул WB»
   с каталогом.

Если снимок данных не подключён — вкладки покажут пустое состояние вместо ошибки.

## Что считается автоматически

Модель повторяет формулу WB «Итого к оплате» (сверена на суммах всего магазина
с точностью 99,99%):

| Показатель (Главная) | Формула |
|---|---|
| Итого к оплате от WB | К перечислению − логистика − штрафы − удержания − хранение − операции приёмки − стоимость лояльности − возмещение издержек |
| Прибыль за период | Итого к оплате − Себестоимость проданного − Реклама |
| ДРР | Реклама ÷ Выручка |
| Удержания и издержки WB | Выручка − Итого к оплате (всё, что забрала WB) |
| Маржинальность | Прибыль ÷ Выручка |
| Себестоимость проданного | (продано − возвращено) × себестоимость за шт из каталога (налог уже в с/с) |

Учитываются **все типы строк** отчёта (продажа, возврат, логистика, хранение, штрафы,
удержания, возмещение издержек), а не только продажи. «Возмещение издержек по перевозке/
складским операциям» — это **расход** (продавец возмещает WB её издержки), поэтому
вычитается. Строки без «Даты продажи» (служебные) относятся к периоду отчёта в целом.

WB выдаёт за неделю **два отчёта** — «Основной» (он же «по заказам») и «По выкупам».
Их нужно грузить оба: дашборд складывает их (строки разных отчётов не пересекаются по
отпечаткам, поэтому не задваиваются). Отчёт может быть огромным — грузите его частями
(хоть по строкам): одинаковые строки распознаются по отпечатку и не считаются дважды,
после каждой загрузки показывается «добавлено N новых, K уже были».

**Реклама** загружается отдельно (WB Продвижение → «История затрат»). Дашборд берёт
кампании, начинающиеся с «18+», и разносит расход по артикулам (последние цифры в
названии кампании), считает ДРР и вычитает рекламу из прибыли — в том числе в разрезе
каждого артикула. Налог отдельно не считается — он уже заложен в себестоимость.

Если для товара не указана себестоимость — дашборд предупреждает баннером и не прячет
это в цифрах.

Кроме P&L дашборд считает: % выкупа и динамику заказов в штуках и деньгах
(вкладка «Динамика»); прогноз дней до обнуления остатка и объём дозаказа с округлением
до контейнеров, с учётом уже едущих поставок (вкладка «Оборачиваемость»); сравнение
двух произвольных периодов по одному товару (вкладка «Товар»).

Заголовки всех таблиц кликабельны — сортировка по любому столбцу, повторный клик
меняет направление.

## Дальнейшие шаги (по желанию)

- **Автоматизация через API продавца WB** — дашборд сам подтягивает отчёты по токену,
  без ручной выгрузки файлов. Делается отдельным этапом поверх текущей версии.

## Стек

Чистый HTML + CSS + JavaScript, без фреймворков и сборки. Графики — inline SVG.
Тёмная/светлая тема, адаптив под мобильные. Разбор XLSX — SheetJS в Web Worker.
Данные пользователя — IndexedDB (отчёты) и localStorage (настройки, тема).
