## Модель безопасности — САМОЕ ВАЖНОЕ

Реальные данные (каталог товаров, история заказов, финансы, реклама) хранятся
**зашифрованными** в `wb-secure.js` (AES-256-GCM, ключ — PBKDF2-SHA256 от
**кода доступа**). Это единственный файл с данными в репозитории — он публичный
(репозиторий публичный), поэтому шифрование — не формальность, а реальная защита.

- **Код доступа НИКОГДА не хранится в репозитории.** Его знает только
  пользователь и передаёт в чате. Если пользователь не дал код в начале
  сессии — **спроси**, не пытайся угадать и не бери из старых сообщений
  этого файла (тут его и не должно быть).
- Плейнтекст-версии данных (`wb-data.js`, `wb-reports.js`) **не коммитятся**
  (см. `.gitignore`) — они существуют только временно в `decrypted/`, которая
  тоже игнорируется гитом. Рабочая директория контейнера эфемерна: между
  сессиями `decrypted/` не переживёт — это ожидаемо, просто расшифруй заново.
- Единственное, что переживает переход в новую сессию, — то, что закоммичено
  в git. Поэтому: **закончил работу с данными → зашифровал → закоммитил
  wb-secure.js.** Не оставляй сессию с несинхронизированным decrypted/.
- Если пользователь просит сменить код доступа — расшифруй старым кодом,
  зашифруй новым, сообщи явно, что старый код перестанет работать у всех.
- **Код доступа и любые секреты — НИКОГДА в файлах репозитория**, включая служебные скрипты: код берётся из
  аргумента или переменной окружения (`WB_CODE`/`VERIFY_CODE`). 26.08–18.10.2026 код лежал вписанным в скрипт
  открытым текстом 53 дня — поэтому его и сменили. Перед каждым коммитом: `git grep -n "<код>" HEAD` — пусто.

## Файлы репозитория (кратко; подробно — `справочник/данные.md`)

- `index.html` — весь сайт. Снимок грузится динамически: `data-version.json` без кеша → `wb-secure.js?v=…`.
  Руками версию не бампать, статический `<script src="wb-secure.js?v=…">` не возвращать.
- `data-version.json` — версия снимка + отпечаток `build` (sha1 index.html). Ставит git-хук `.githooks/pre-commit`,
  когда в коммит попадает `index.html`. **В новом контейнере включи хук: `git config core.hooksPath .githooks`.**
- `wb-secure.js` — единственный файл с данными, зашифрован и сжат (`zip:"gzip"`). Внутри `REAL_DATA` +
  `BAKED_FINANCE` + `BAKED_ADS` + `BAKED_FUNNEL` + `MODELED_FINANCE`.
- `scripts/*.cjs` — офлайн-инструменты (перед первым запуском `cd scripts && npm install`). `decrypted/` — плейнтекст,
  gitignored, эфемерный. `справочник/` — тематические памятки.

## Рабочий цикл с данными

```
node scripts/decrypt.cjs <код>     # → decrypted/wb-data.js + wb-reports.js
# … правка через скрипты (справочник/данные.md) …
node scripts/encrypt.cjs <код>     # → wb-secure.js (с самопроверкой)
git add wb-secure.js data-version.json && git commit && git push
```
Код передавай скриптам аргументом или через переменную окружения, в файлы не пиши (см. безопасность).
**После ЛЮБОЙ заливки остатков (ВБ, Ozon, свой склад)** — `node scripts/resupply-report.cjs` и сообщить продавцу
минимум: к отгрузке всего / на Ozon / на ВБ · сколько позиций нечем закрыть · что срочное (его просьба).
**Понедельник — закрытие недели оценкой:** `wb-extend-orders.cjs` → `bake-funnel.cjs` → (`wb-buyout-window.cjs`
по сводному) → `model-finance.cjs` → encrypt. В ответе: выручка · итого к оплате · себестоимость · реклама ·
прибыль · маржа, с пометкой «оценка». **6-значный код с пометкой «новый товар»** → сразу
`new-codes.cjs add "<коды>"`, при каждой заливке `new-codes.cjs check <файлы>` (подробно — `справочник/данные.md`).

## Капканы, которые бьют в любой задаче (подробности — в справочнике темы)

- **Скрипт, переписывающий `decrypted/wb-reports.js`, обязан переносить `MODELED_FINANCE`** (и `BAKED_FUNNEL`);
  **`ozon-build.cjs` переписывает `RD.ozon` целиком** и обязан переносить из `ozon.meta`: `terms` · `revBase` ·
  `buyoutWin` · `unitReports` · `adSpend` · `clusters` · `clusterHistory` · `ozzOn` · `orderFee`. Новое поле
  в `ozon.meta` от другого скрипта — добавляй в перенос. Пропажа не даёт ни ошибки, ни пустой таблицы.
- **`costAt`/`costOf` смотрят в карты АКТИВНОЙ площадки**: на «Всего» себестоимость ВБ падала в ноль (стоило
  7,3 млн «прибыли из воздуха»). Фолбэк `wbCostBySku()`, прибыль ВБ на «Всего» — через `recWithMp`. У Ozon своя
  карта `ozCostMap()` (с фолбэком `meta.costBySup`).
- **Логика продублирована в index.html и скриптах — правишь одно, правь второе** (сверка до рубля/штуки):
  `ozFinRows`/`ozApplyAdFact`/`ozOrderFeeOn`/`ozUnitReports`/`ozBuyoutFor`/`ozCostMap`, дата РЕК-23
  `OZ_FEE_REPORT_ONLY_FROM` (там `FEE_ONLY_FROM`) ↔ `scripts/ozon-finance.cjs`;
  подсорт (`resupplyRows`, `topUpTrucks`, `truckFill`, `truckConsolidate`, `packTrucks`, `WHS`/`whKey`, `ozTransitEff`,
  партии `inbKeys`, выкуп `buyoutInfo`, фильтр «на вывод») ↔ `scripts/resupply-report.cjs`; дата подённого файла —
  `wb-extend-orders.cjs` ↔ `bake-funnel.cjs`; имя файла с «_» — `ozon-ads-spend.cjs` ↔ `update-ads-perf.cjs`;
  фильтр `spendOnly` — `ad-part.cjs` ↔ `update-ads-perf.cjs`; «Итого к оплате» — воркер index.html ↔ `lib/parse-wb.cjs`;
  колонки `ОПЫТ.md` — `OPYT_COLS`/`opytMap` ↔ `COLS` в `scripts/opyt.cjs`.
- **Новый кеш от каталога/данных — сбрасывай в `hydrateData` И в `fdbRefreshCache`**, иначе после перезаливки
  останутся старые цифры.
- **% выкупа действует с даты замера (`builtAt`) и вперёд, прошлое не пересчитывается** (обе площадки).
  «Выкуплено на сумму» из `money[…][1]` заморожено на момент выгрузки — показываем ТОЛЬКО оценку
  `заказано × % выкупа`.
- **Ozon: база выручки — «Предельная цена», соинвест НЕ вычитается**; витрина Ozon («Заказано на сумму») считает по
  цене для покупателя — с дашбордом напрямую не сравнивать (разница ~36%, это норма).
- **ДРР: на Ozon 10% — МИНИМУМ (держать соинвест), на ВБ 7% — ПОТОЛОК.** Обе цифры — в выкупе. Разные константы
  (`OZ_DRR_GOAL`/`AD_DRR_GOAL`), сравнения в разные стороны.
- **Месяц: Ozon календарный, ВБ — целыми неделями по ЧЕТВЕРГУ.** Неделя — только пн–вс; «в моменте» — день против
  предыдущего дня; «последние 7 против предыдущих 7» не используем. Даты границ печатай из данных.
- **«На вывод» скрывается ОДНИМ флагом `showOut`** по определению `recOutSups()` (все карточки кода «На вывод»);
  деньги скрытых выносятся отдельной строкой, а не пропадают. Своих фильтров в рендерах не заводи. Исключение —
  «Остатки» (ЗАП-06): код виден, пока где-то есть остаток, плашки нет (`stkRows`).
- **Объект состояния сортировки не пересоздавать** (`wireSortable` держит ссылку) — менять поля.
  **SheetJS в браузере не подключать** (CDN закрыт) — выгрузки идут своим мини-райтером `xlsxDownload`.
- **Ловушка `resupplyRows`: там уже есть `const rest`** — одноимённая `const` даёт SyntaxError и белый экран.
- **Пять тем: цвета — только токенами** (`cssv("--…")`/`var(--…)`, белый на акценте — `var(--on-accent)`), правила для
  тёмной — через `:root[data-scheme="dark"]`; новая справка — только `.howto[data-fold]`, без своих `<details>`
  (подробно — `справочник/вкладки.md`, «UI-паттерны»).

## Публикация на GitHub Pages — проверяй, что доехало

Деплой («pages build and deployment», ветка `claude/wb-dashboard-html-0kxavb`) идёт ~5 минут, а **новый push ОТМЕНЯЕТ
незавершённый деплой предыдущего** — сайт залипает на старой версии. Поэтому: копи правки и **пушь одним

`claude/wb-dashboard-html-0kxavb` и `claude/wb-dashboard-continue-jmxwht` — пушить во все три.

## Стиль работы с продавцом

- **ЕГО ВОЗРАЖЕНИЕ — ЭТО НЕ СПОР, А ВВОД ФАКТА. РОЛИ РАЗДЕЛЕНЫ, И ОН ИХ НАЗВАЛ САМ** (08.10.2026: «я с тобой
  не спорю а дискусирую — ты мозг в нашей команде, я просто делюсь фактами, где ты тоже ошибаешься, моя
  задача помочь тебе помочь мне»). Рабочее соглашение, из него четыре правила:
  · **Расчёт и линию держишь ТЫ.** Свернуть рекомендацию «чтобы не спорить» — худшее: он останется без
    расчёта, ради которого всё затевалось.
  · **Но и защищать вывод из упрямства нельзя.** Он добавляет то, чего в данных нет (цены конкурентов,
    механику площадки, историю ассортимента, опыт) — проверяй такой факт по данным, а не на слух.
  · **Разбирай вывод на основания и говори, какие отпали, а какие остались** («из четырёх оснований одно
    снято, три в силе»).
  · **Признавай ошибку прямо и цифрой**, без оправданий и самобичевания: что посчитал неверно, как
    правильно, что это меняет.
- **ТРИ ЕГО ПОПРАВКИ ЗА ОДИН ДЕНЬ (08.10.2026) — ОБРАЗЦЫ ТОГО, ГДЕ Я ОШИБАЮСЬ СИСТЕМНО:**
  · **Категорийное среднее — НЕ цена сравнимых товаров** («толокар в 1,5–1,9× дороже рынка» по средней цене
    ниши, а внутри сегмента «с родительской ручкой» 487187 оказался на 7,1% дешевле среднего).
    **Ценовой разрыв считай только внутри сегмента сравнимых товаров.**
  · **«Если конверсии одни и те же, меньше показов = меньше переходов» — и он прав**: моё «ночные часы
    конвертят на 18% хуже» оказалось шумом (z = 0,6 при пороге 1,96). **Любое «эта группа
    часов/дней/товаров работает хуже» — только с z.**
  · **«Органика может не работать без рекламы, нас перебьют» — тоже верно**: без рекламы по верхним
    запросам товара нет вовсе (позиции 150 и 800 при глубине просмотра 40–57).
- Пользователь — не разработчик: результат человеческим языком, без жаргона, коротко «что сделал / что
  проверил / что дальше».
- **ВСЕГДА НАЗЫВАЙ ПЛОЩАДКУ — В ЗАГОЛОВКЕ, В ТАБЛИЦЕ И РЯДОМ С КАЖДОЙ ЦИФРОЙ** (03.09.2026: «про какой из мп
  ты начинаешь говорить? если по вб, так и пиши»). Два кабинета с разными цифрами и артикулами; цифра без
  площадки бесполезна.
  · Заголовок раздела несёт площадку («Ozon: что произошло»), таблицы тоже; «арт. Ozon 487175», а не голый код.
  · **НЕ МЕШАЙ ПЛОЩАДКИ В ОДНОМ РАЗДЕЛЕ** (пример с ВБ в разборе Озона читался как разбор ВБ): пример
    с другой площадки — отдельным блоком с подписью или не приводить.
  · В общих списках (что прислать, чего не хватает) у каждого пункта — ВБ, Ozon или обе.
- **ЛЮБОЕ УТВЕРЖДЕНИЕ В СТЕПЕНИ — ТОЛЬКО ПОСЛЕ ПРОГОНА ПО ВСЕМУ РЯДУ** (03.09.2026: «проверь лучше несколько
  раз, я тебе доверяю и не хочу подставляться»). Он пересказывает мои цифры руководителю — ошибка бьёт по
