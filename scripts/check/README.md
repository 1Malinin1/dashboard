# Проверки Dashboard

## Полный контрольный прогон

Из корня проекта запустите `sh scripts/check/run-all.sh` или `node scripts/check/run-all.cjs`. Обе команды запускают вкладки, прибыль Ozon и полные машины. Каждая проверка проверяет свои результаты. Код выхода 0 означает успех всех трёх, 1 — ошибку проверки или подготовки, 3 — отсутствие `VERIFY_CODE`. Git-хук использует эту же оболочку для изменений сайта, `calc/` и снимка при заданном `VERIFY_CODE`.

Нужны установленные зависимости из `scripts/package-lock.json`, Chrome или Chromium и зашифрованная пара `wb-secure.js` / `data-version.json`. В Windows укажите установленный `chrome.exe` через `PW_CHROME`. Windows запускает его с включённой песочницей. В Linux действует прежний путь `/opt/pw-browsers/chromium` или `PW_CHROME`.

### Ввод кода в PowerShell

Выполните блок в обычном локальном PowerShell из корня репозитория. Наберите код в скрытом приглашении `Read-Host`. В истории останется только текст команд. Значение передаётся через окружение одного дочернего процесса Node. Тесты снимают флажок запоминания до ввода, проверяют хранилище браузера после входа и закрывают временный браузер.

```powershell
& {
    $ErrorActionPreference = 'Stop'
    $start = [System.Diagnostics.ProcessStartInfo]::new()
    $start.FileName = (Get-Command node.exe -CommandType Application -ErrorAction Stop | Select-Object -First 1).Path
    $start.WorkingDirectory = (Get-Location).Path
    $start.Arguments = 'scripts/check/run-all.cjs'
    $start.UseShellExecute = $false
    foreach ($name in 'DEBUG','PWDEBUG','NODE_DEBUG','NODE_OPTIONS','WB_CODE') {
        $start.EnvironmentVariables.Remove($name)
    }
    $secret = Read-Host 'Код Dashboard' -AsSecureString
    try {
        $start.EnvironmentVariables['VERIFY_CODE'] = [System.Net.NetworkCredential]::new('', $secret).Password
        $check = [System.Diagnostics.Process]::Start($start)
    } finally {
        $start.EnvironmentVariables.Remove('VERIFY_CODE')
        $secret.Dispose()
    }
    try {
        $check.WaitForExit()
        if ($check.ExitCode -ne 0) { throw "Dashboard: код выхода $($check.ExitCode)" }
    } finally {
        $check.Dispose()
    }
}
```

### Временные файлы и сервер

Запуск создаёт уникальный `dashboard-check-*` в системном временном каталоге пользователя вне проекта. В него копируются ровно семь публичных ресурсов страницы и два скрипта для сверки. Браузер и скриптовый расчёт читают одну копию снимка. HTTP-сервер слушает `127.0.0.1` на свободном порту (конкретный порт можно задать через `PORT`). Он отдаёт только `index.html`, `favicon.svg`, `data-version.json`, `wb-secure.js`, `ОПЫТ.md`, `calc/ozon-fin.js` и `calc/resupply.js`. Остальные пути возвращают 404.

Расшифровка, временный скрипт, JSON и XLSX записываются внутрь созданной копии. При успехе зашифрованная пара побайтово сверяется с рабочей и весь каталог прогона удаляется. При ошибке выводится путь для локальной сверки. После разбора удалите только этот конкретный временный каталог. При прерывании процесса каталог также может остаться. Рабочая `decrypted/`, исходные отчёты и несохранённые изменения в очистку не входят. JSON и XLSX не публикуйте.

### Критерии трёх проверок

- **Вкладки.** Скрипт нажимает все 10 кнопок вкладок, проверяет выбранную вкладку, видимую панель, содержимое и переключатель площадки. При двух площадках ожидается 26 состояний: восемь вкладок × три режима и два самостоятельных экрана. «Остатки» объединяют собственные склады, ВБ и Ozon. «Финансы» относятся к ВБ. Для снимка только с ВБ обход ожидает 10 состояний. Финансовый контроль Ozon и три выгрузки полного прогона требуют данных Ozon. Для штатных пустых состояний проверяются сообщения или элементы внутри целевой панели. Ошибки страницы и консоли завершают проверку неуспешно.
- **Прибыль Ozon.** Контроль 1–14 октября 2026 года берётся строго из `oct14`: прибыль 2 840 276 ₽ и реклама 1 242 047 ₽. `oct` охватывает весь доступный октябрь. В каждой строке проверяется конечность и величина разницы между удержаниями и суммой «выручка × фиксированная ставка + реклама», допуск 0,01 ₽. Обязательны `mpBad = 0`, `feeChain = 0`, `feeOutside = 0` относительно фактического окна отчётов и отсутствие ошибок браузера. `aug`, `sep` и состав расходов доступны в детализации.
- **Подсорт.** Проверяются строки по кодам, складам и направлениям, резерв, план сайта и скрипта, ограничения склада и добора, полные машины и отказы. Не допускаются расхождения расчётов и ошибки браузера. Все шесть именованных сценариев `truckFill` должны пройти. В режимах Ozon, ВБ и «Всего» скачиваются три XLSX через кнопку сайта. Проверяются имя файла, три листа, колонки выбранной площадки, отгрузка по коду 1С и итоги подсорта, состав отправляемых и отменённых машин, штуки и паллеты по каждой машине. Пустой план допустим с предусмотренной строкой пояснения.

В XLSX отгрузка по каждому коду и строка «ИТОГО» должны точно совпадать с расчётом в порядке строк выгрузки. При независимом суммировании тех же строк в порядке расчёта целые итоги также проверяются точно. Для двух дробных итогов допустимы два шага представления числа двойной точности на величине расчётной суммы. Именно такая разница возникла при перестановке слагаемых на рабочем снимке.

Для отдельной диагностики `tabs-smoke.cjs` принимает `URL` или `PORT`, `ozon-profit.cjs` и `full-trucks.cjs` принимают `URL` локального ограниченного сервера. Для сверки машин сервер должен отдавать ту же версию проекта и снимка. У `full-trucks.cjs` можно задать существующий `OUT_DIR` вне проекта: результаты останутся в новом уникальном подкаталоге. Обычный полный прогон сам управляет каталогами и сервером.

Тесты записи и восстановления запускаются отдельно командой `node --test scripts/check/encrypt.test.cjs`. Все 25 используют вымышленные данные и временные каталоги, включая прежний формат, повреждение файлов, конкуренцию, принудительную остановку, целостность резервов, отказ повторного запуска и восстановление исходной пары.

## Отдельная будущая задача — покрытие вложенных сценариев

Верхнеуровневый обход подтверждает открытие каждого экрана. В таблице перечислены вложенные действия и расчёты, для которых потребуется отдельное согласование проверок.

| Рекомендации | Срочность и деньги, «Просело / Выросло / Всё», деревья, переход с фильтром и его сброс | Недельная диагностика, приоритет задач, план чистой прибыли |
| Главная | Недели и месяцы, поиск и категории, «На вывод», ввод недостающей себестоимости ВБ, CSV | Выплата и прибыль ВБ, себестоимость по коду и дате, границы месяцев, суммирование площадок |
| Динамика заказов | По дням и свод, пресеты и свои даты, поиск, категории, сортировка, Excel | Штуки, рубли, выкуп, разные даты покрытия, сравнение с предыдущим периодом |

Сквозные сценарии для будущей задачи включают ошибочный код и повторный вход, блокировку, восстановление вкладки и площадки, темы и мобильную навигацию, подсказки, складную справку, множественный выбор, согласованность фильтров с экспортом и ссылками на карточки. Аудит источников и полноты заказов, складов, производственных партий и кодов 1С требует сверки с исходными отчётами.

### Детали для приёмки будущих сценариев

- **Периоды.** На «Главной», «Финансах» и «Аналитике» состав кнопок зависит от глубины истории: до восьми недель, закрытые месяцы, идущий месяц и весь период, а при отсутствии именованных месяцев — скользящие интервалы. У «Динамики» есть вчера, 7/30/90 дней, весь период и собственные даты. У «Остатков» — 7/14/30 дней, вся история и календарь с доступностью замеров. Для рекламы нужны текущий период, сравнение и его сброс, периоды выгрузок, закрытые недели и месяцы.
- **Запас и производство.** Горизонты — до выхода партии или 60/90/120/180 дней. У ВБ есть решения «Не хватит и Озону», «Поднять цену», «Разогнать · маржа < 10%», «Отгрузить на ВБ», «Разогнать», «Держать». У Ozon — «Отгружать сейчас», «Кончится до партии», «Хватит до партии», «Нет продаж». У общего вида — «Не хватит до партии», «Хватит», «Избыток», «Нет продаж». Каждый режим также предлагает «Все». В «Разборе товара» оборачиваемости вводятся код, количество в проформе и горизонт 1–24 месяца.
- **Колонки и поиск.** Для оборачиваемости важны места хранения, потребность, отгрузка, приход, покрытие, темп, выкуп, закуп и статус. Для запаса — решение по площадке и статус производственного заказа. Для рекламы ВБ — группа, категория, артикул, код 1С, склейка, ABC, запас, решение по кандидату, состояние кампании, ДРР, CPO и источник выкупа. Отдельные сценарии — несколько выбранных значений, сброс, пересечение с поиском и перенос фильтра из рекомендаций.
- **Специальные экраны.** «Всего» на «Товаре» и «Рекламе» показывает подсказку о выборе площадки. В оборачиваемости «Всего» позволяет смотреть общий подсорт и сквозной разбор товара. В остальных четырёх видах предлагается выбрать площадку. На «Аналитике» общий экран сопоставляет площадки. Для графика товара нужны все шесть метрик: заказы, заказано в рублях, выкуплено в рублях, CTR, конверсия в заказ и процент выкупа.
- **Независимые сверки.** Для прибыли Ozon источник — `calc/ozon-fin.js`, для подсорта — `calc/resupply.js`. Дальнейшие сверки должны охватить реализацию ВБ и периоды обеих площадок в `index.html`, даты выкупа и себестоимости, план новинки в `repricer-plan.cjs` и `plan-review.cjs`, партии и приходы в `scripts/lib/prod-arrivals.cjs`, собственные коды и полноту входов в `data-audit.cjs`. Контроль чисел ведётся отдельно от проверки отображения.
